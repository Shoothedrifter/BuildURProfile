# 简历核对补充内容 P0 实施记录（2026-11-11）

本记录归档已完成阶段的决定和验证结果。当前合同、接口及运行方式以[文档导航](../README.md)所列文档为准；原详细 Spec/Plan 可在 Git 历史中查看。

## 范围与结果

- 保留会话保护的原 PDF 和来源摘录供人工核对，上传起 30 天自动清理；用户可以提前删除。浏览器旧解析路径继续兼容。
- 编辑页按固定十模块和稳定条目 ID 确认内容，低置信度条目需显式标为「已核对」，待核对内容阻止进入风格页。已选条目可添加补充文字、命名链接和图片；无效输入在本地和服务端校验。
- 新 `resume-v2` 只投影已确认且可见的展示字段。服务端核对 revision、会话与图片归属，将所选图片复制到独立作品资产，再把无 PDF 原文和来源块的 brief 交给 `python-agent-v3`。旧 `resume-v1` 项目和 v2 任务保留兼容路径。
- 无肖像生成成功后幂等创建未付款作品草稿。Web 预览、项目编辑、受权限校验的分享和 ZIP 导出使用同一条目结构；工作与校园经历独立，正文保留段落，项目图片不随原简历到期而丢失。
- 单张图片上限 5 MiB，单条 6 张，整份 24 张且 50 MiB。刷新后可查看、恢复或逐张删除未保存图片；保存时不批量清理其他编辑标签页正在使用的上传。迟到上传按稳定条目 ID 归位，已删除条目的迟到图片被释放。

## 审查与取舍

独立审查发现四项重要问题，均已修复并用先失败、后通过的回归测试覆盖：成功任务恢复覆盖后来编辑的项目；图片上传回包晚于条目移动或删除；未保存图片在刷新后占用配额且无法处理；修改技能后跑马灯仍显示旧文案。审查没有关键问题或待处理的次要问题。

在已有 `dev/noodle` 开发工作区实施，以便保留本机联调状态；并发修改需检查工作区。合同、界面、存储和渲染共用版本边界，先整体验证，再用一次中文提交保存主体，另以中文提交保存审查修复。未保存图片采用属主可见的恢复列表和显式删除，避免误删另一标签页尚未提交的图片。

Wibi 肖像仍限本机非商业预览；带肖像任务不自动建可付费交付项目。OCR、自动保存、离线历史、条目拆合和新模板不在此阶段范围内。
