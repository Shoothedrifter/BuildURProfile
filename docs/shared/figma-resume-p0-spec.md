# Figma 简历核对闭环 P0 Spec（已实施，待最终审查）

**日期：** 2026-11-11  
**设计参照：** [Figma v2：解析与补充](https://www.figma.com/design/RyTQa3dPW8cy85iBpmpRUY/%E6%94%AF%E4%BB%98%E5%AE%9D%E9%BB%91%E5%AE%A2%E6%9D%BE?node-id=67-154)，同页的「项目条目展开」「关键状态与弹窗」。画板是交互参考，技术与隐私边界以仓库合同和本 Spec 为准。  
**实施授权：** 用户已审阅并要求开始开发；24 张 / 50 MiB 上限作为本轮实施值。

## 1. 目标与现状

用户在 `/editor/:resumeId` 核对 Agent 草稿、逐条补充说明、链接和图片，确认后完成测评并生成作品。补充内容必须在预览、保存的项目、付费分享和导出中一致可见；「待确认」必须能由用户明确完成；界面不能创建一条服务端必然拒绝保存的数据。

现状是 `resume-draft-v1` 已保存条目补充信息，但 `projectConfirmedResume` 仅投影标题、正文和勾选的 facts。`resume-v1`、生成 brief、Python 合同和 Showcase 均不支持这些补充信息。`needsReview` 在编辑后不会清除；空 URL 行和第 7 张图片仍可在界面产生，但保存会失败。原 PDF 的会话保护预览和来源摘录已经存在，必须保留。

## 2. 范围与决定

### 本次 P0

1. 十个固定简历模块中的**已展示条目**可携带补充文字、链接、图片说明和图片；隐藏模块、未勾选条目的补充信息不得进入生成任务。
2. 每条补充文字最多 500 字符；链接最多 5 条，含可选名称（最多 80 字符）和必填 HTTP(S) URL（最多 2000 字符）；图片最多 6 张，PNG/JPEG/WebP，单张最多 5 MiB，说明最多 80 字符。P0 全份简历最多 24 张、合计最多 50 MiB，上传前在界面说明并由服务端核对。这是为单机 SQLite 和交付包设置的额外上限。
   已确认内容的生成 brief 继续受 256 KiB 上限约束；超出时在确认页显示具体的内容体积错误并允许用户修改，不截断、不丢弃已保存草稿。
   字符限制按 Unicode 码点计数，与私有草稿 Schema/Python 校验保持一致；Web 计数和裁剪不能用 UTF-16 长度误判表情符号。
3. 低置信度条目保留警示，用户可明确选择「已核对」。确认进度统计 `needsReview === false` 的十个模块；空模块视为已核对。编辑文字本身不自动等于核对。隐藏待核对模块须先由用户确认隐藏，才算核对完成。仍有待核对条目时阻止进入风格页，并定位首个待核对项。
4. 保存时只提交完整且有效的链接；完全空白的本地新增行不入草稿，有名称但无 URL、无效协议或超限时就近提示并阻止保存。图片上传前和服务端同时校验大小、实际图片格式及尺寸；到上限禁用上传。取消上传、删除条目或删除草稿后不能留下可访问的孤儿资产。
5. 确认内容采用新的 `resume-v2` 展示合同。生成图只接收确认后的文本和图片 ID，不接收 PDF 字节、来源块、PDF 路径、置信度、隐藏字段或未勾选条目。旧 `resume-v1` 项目和草稿继续可读。
6. 用户选择生成时，服务端校验图片 ID 属于当前会话/简历且确被确认，并将所需图片字节复制到独立的私有作品资产；生成配置只保存稳定资产 ID。生成成功即创建同会话的**免费作品草稿**并关联资产，重复回调/刷新不重复建项目；付款资格仍为未解锁。原 PDF、来源块及草稿仍按上传起 30 天清理；已生成作品的图片按项目生命周期保存，删除项目时按引用关系清理。生成失败或未形成项目的复制品限期回收。
7. 预览和项目编辑通过受会话保护的 `/api/showcase-media/:imageId` 读取作品图片；分享通过 `/api/shares/:token/media/:imageId` 读取，且必须核对有效分享令牌、付款资格和该分享快照确实引用图片。撤销/过期/未付款时拒绝；导出 ZIP 包含 `assets/*` 图片文件。文本、链接、图片在 Web 预览、分享和导出中按同一条目顺序出现。
8. 保留编辑页的原 PDF 预览栏及逐条来源摘录。该栏仍使用会话保护的 `/api/resumes/:id/source`，不打包到生成作品、分享或导出。

### 不进入本次 P0

重解析覆盖/补空、自动保存、断网历史、用户拆分/合并、拖拽、自定义第十一个模块、扫描件 OCR、任意网页模板和新支付流程。现有上下移动可继续用于条目排序；「其他内容」可承载自定义标题。Figma 的「一键发布」文案须遵守现有付费资格检查，不能绕过支付。

## 3. 合同和数据流

### 私有草稿

继续使用 `resume-draft-v1`，给 `supplements.links[]` 增加可选 `label`（旧草稿只有 `url` 时读为 `label: ""`）。新增条目保持稳定 `itemId`。`needsReview` 是用户核对状态；低置信度仍由 `confidence/segmentationConfidence` 显示警示，不因用户核对而伪造更高置信度。已核对的操作必须写入草稿并参与 revision 冲突检测。

### 确认展示合同

定义 `StructuredResumeV2`：`{version:"resume-v2", sections: ResumeSectionV2[]}`。`sections` 只含可见且至少一条已选内容的固定模块，按既有十模块顺序排列；每个 section 为 `{kind, items}`，每个 item 为 `{itemId,title,details,facts,supplement}`。`supplement` 为 `{text,links:[{label,url}],images:[{imageId,caption}]}`。基本信息和求职意向条目的 `facts` 也遵守逐字段 `included`，其未勾选字段不得由标题、正文或补充文字绕道泄露。`itemId` 仅用于稳定关联和顺序，不作为来源证据。

`ResumeContent.profile/expertise/projects/workExperience/campusExperience/education` 继续作为当前骨架的兼容投影。`resume-v2.sections` 是十模块及补充内容的唯一结构化真相；渲染器不得把兼容投影再显示一遍造成重复。Agent `resume.compose.v3` 只透传并验证已确认内容，不调用 LLM 改写补充内容。若现有展示位置可复用，沿用 Marquee + StackedCards 和三种皮肤。

新 Agent 路径的 `/api/generations` 请求只提交 `resumeId`、已读取的 `revision`、角色和测评答案；服务端重新读取同会话草稿、核对 revision/待确认状态，再执行 `projectConfirmedResume`，不能信任浏览器自报的 `content`。旧浏览器兼容入口仍按原 `content` 请求处理。服务端在入队前校验 `resume-v2` 和图片所有权，复制已选图片到私有作品资产并记录任务引用；幂等重试复用同一副本。生成图版本由 `python-agent-v2` 升为 `python-agent-v3`，Skill 为 `resume.compose.v3`，TS/Python 模型、JSON Schema 和黄金样例同步升级。部署期间旧 v2 任务仍须完成或明确失败；新任务只写 v3。已保存的 `resume-v1`/旧 `DesignConfig` 由兼容分支读取，不强行迁移。

作品资产 ID 在服务端校验后可随 v3 brief/config 流转；图片字节、上传文件名、PDF 来源和密钥不得进入 Agent checkpoint 或日志。项目保存时关联作品资产；分享快照保留当时引用的资产，项目删除或分享撤销按权限立即失效。未挂项目的任务资产最多保留 30 天，并由有界清理任务回收。

## 4. 页面行为

| 情况 | 预期 |
| --- | --- |
| 新增空白链接并保存 | 丢弃完全空白行；保留现有有效数据；不出现通用 `INVALID_DRAFT` |
| 链接有名称但 URL 为空、`javascript:`、超长 | 定位本条链接并显示可修复提示；不发保存请求 |
| 第 6 张图片已存在 | 上传入口禁用并显示上限；并发上传也由服务端总量核对 |
| 低置信度条目被用户核对 | 待确认数减少，警示仍可查看；保存/刷新后保持已核对 |
| 隐藏未核对模块 | 提示确认隐藏；完成后不进入作品，确认进度可归零 |
| 生成前原 PDF 已过期 | 拒绝用失效私有图片创建新生成任务；已独立保存的作品继续可读 |
| 生成/分享/导出 | 已选补充内容一致；旧 `resume-v1` 作品继续正常显示 |
| 生成成功但尚未付款 | 「我的项目」有可继续编辑的免费草稿；不能正式分享或导出 |
| 删除简历或项目 | 简历删除不误删已生成项目资产；项目删除撤销分享并清理无其他引用的资产 |

页面仍为现有三栏（模块导航、编辑、原 PDF），窄屏可将原 PDF 移到编辑区下方或折叠面板。Figma 的两栏视觉稿不能成为删除原件对照的理由。

## 5. 验收与安全边界

- 合成 PDF 与假 Agent 走「上传 → 解析 → 核对/补充 → 保存 → 测评 → 生成 → 预览 → 创建项目 → 分享/导出」；十模块、工作/校园分离、条目顺序和补充内容均正确。
- 隐藏内容、PDF 摘录、`sourceBlockIds`、低置信度数值、未选敏感字段不出现在 brief、checkpoint、项目配置、分享 JSON 或 ZIP。
- 跨会话图片/草稿请求拒绝；分享资产在未付款、过期、撤销或项目删除后不可读；导出只使用当前项目的图片。
- 30 天删除原 PDF 后，已保存的作品图片仍可预览、分享和导出；未形成项目的任务资产按期回收。
- 旧 `resume-v1` 项目、旧生成任务和旧无补充字段的草稿能读；无真实 PDF、密钥和图片字节进入测试日志或 Git。

## 6. 方案取舍

**采用：** 独立作品资产 + `resume-v2`，因为图片 ID 可穿过 Agent 而不带字节，作品不依赖 30 天的原件生命周期。**未采用：** 把图片转成 Data URL 放入 256 KiB 的生成 brief 或 8 MiB 的配置；按画板直接增加任意模块；在用户编辑时自动清除低置信度警示。这些选择分别会冲击大小上限、固定模块合同和核对语义。
