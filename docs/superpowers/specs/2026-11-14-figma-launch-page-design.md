# Figma 启航页产品级融合设计

## 意图与背景

将根路径 `/` 从“旧生成工作流的首页状态”升级为面向首次访问者的产品启航页，并以 Figma 节点 `67:74`（“PRD 更新版 / 01 启航页”）为视觉与信息架构基准。页面的首要任务是让用户理解产品价值，并进入 `/upload` 的 Agent 简历解析流程；现有项目管理、作品样例和旧浏览器解析能力继续可用，但不再与主路径争夺注意力。

当前根页面由 `App`、`BuilderExperience` 和 `BuilderChrome` 共同承载。营销内容与旧浏览器解析状态机耦合，首页使用粗黑描边、硬阴影和开发演示式文案，缺少 Figma 中完整的价值说明、案例和三步流程。`/upload` 已经是独立的 Agent 上传页，因此首页无需复制上传逻辑。

## 目标

- 在桌面端按 Figma 的 1280px 内容宽度、暖白背景、桃色主按钮、浅灰棕边框和克制圆角建立完整首页。
- 保留 Figma 的五段信息层级：导航、Hero、四项产品价值、三类作品案例、三步流程与页脚。
- 将“上传简历，免费开始”和“开始生成”统一指向真实 `/upload` Agent 流程。
- 让顶部“查看样例”和 Hero 次按钮平滑滚动到案例区，案例卡按钮进入现有真实 Showcase 样例。
- 保留“我的项目”入口，并继续打开现有受会话保护的项目弹窗。
- 保留旧浏览器解析，但降级为明确标记的兼容入口，进入现有 `phase="upload"` 流程。
- 提供 1440px、平板和手机端的响应式布局，并满足键盘访问、语义结构、焦点态和减少动态效果偏好。

## 非目标

- 不改动 `/upload`、`/editor/[resumeId]`、`/style/[resumeId]` 或生成、支付、交付工作流。
- 不创建新的作品样例数据；三张案例卡复用现有 Showcase 样例入口。
- 不创建尚无产品内容的隐私政策、服务条款或联系我们页面。
- 不把 Figma 当作像素截图直接硬编码，也不引入新的 UI 框架、字体包或运行时依赖。
- 不移除旧浏览器解析代码，也不改变其合同、解析结果或测试数据。

## 反目标

- 不允许首页出现无响应按钮、假链接或指向不存在页面的导航。
- 不允许为了匹配首页视觉而全局改写 `.proof-card`、`.proof-button` 等内部工作流样式。
- 不允许首页重复请求 PDF、支付或生成接口。
- 不允许在移动端依赖横向滚动才能阅读 Hero、价值卡、案例卡或步骤。

## 约束

- 延续 React、Next.js App Router、TypeScript 和现有 CSS，不新增依赖。
- 使用仓库现有 `apps/web/public/logo.png`；其尺寸为 150×78，与 Figma Logo 资产尺寸一致。
- 根路径仍由 `App` 管理，以保留分享哈希、支付返回和旧状态机兼容；仅把 `phase="landing"` 的表现拆为独立组件。
- 组件类名使用独立的 `launch-*` 命名空间，避免影响 Agent 上传和编辑器页面。
- commit 信息使用简体中文；函数名、变量名和专有名词保留英文。

## 方案比较

### 方案一：产品级融合（采用）

按 Figma 重建启航页，同时将现有真实能力映射到对应入口。Agent 上传为主路径；“我的项目”和旧浏览器解析降级但保留。视觉与产品语义均得到修正，且不牺牲现有功能。

### 方案二：完全照搬 Figma

只保留 Figma 显示的导航和按钮。视觉最接近，但会隐藏项目管理与兼容解析，也会诱发隐私政策等假链接，因此不采用。

### 方案三：给现有首页换皮

维持旧 Hero、角色卡和 FAQ，仅调整颜色与边框。改动较小，但不能解决信息架构、主路径和完整案例区缺失的问题，因此不采用。

## 页面结构与行为

### 1. 导航

- 左侧使用现有 150×78 Logo，点击回到页面顶部。
- 中间“查看样例”滚动到 `#launch-examples`。
- 右侧保留低强调的“我的项目”，并放置桃色主按钮“开始生成”，后者为普通链接 `/upload`。
- 桌面端保持单行；手机端 Logo 与主按钮占首行，样例和项目入口置于下一行，不出现遮挡。

### 2. Hero

- 左列使用 Figma 主文案：“把一份 PDF 简历，变成你的个人网站”。
- 副文案说明 Agent 自动解析、模块补充和可分享主页。
- 主按钮链接 `/upload`；次按钮滚动到案例区。
- 两个按钮下方提供低强调文字按钮“使用浏览器解析（兼容）”，触发现有 `onPhaseChange("upload")`。
- 右列保留 Figma 的产品预览卡，不使用图片截图：以语义化 HTML/CSS 构建标题、技能概览和两个项目块，保证缩放与响应式清晰度。

### 3. 产品价值

- 标题为“从简历到网站，每一步都有帮助”。
- 四张卡片分别为“AI 智能解析”“模块化补充”“挑选网站风格”“一键发布”。
- 卡片使用白色背景、`#d8c8be` 边框和 12px 圆角，不继承旧 `.proof-card` 的黑色硬阴影。

### 4. 作品案例

- 标题为“看看你的经历，可以变成什么”。
- 三张卡片保留 Figma 的三类定位：体验设计作品集、创意开发实验室、我的项目与故事。
- 卡片缩略区使用 Figma 指定的桃色、浅绿和灰棕背景；文本均为真实页面内容，不加载远程图片。
- 每张“查看样例”以及“查看更多样例”均进入现有 `mock` Showcase，不伪造尚不存在的独立案例。

### 5. 三步流程和页脚

- 三步流程为“上传 PDF →”“确认内容 →”“生成网站”。
- 页脚显示 BuildURProfile、隐私政策、服务条款、联系我们；在相应路由尚不存在时使用普通文本，不显示外链箭头，也不提供虚假点击态。
- 页脚额外提供低强调的“浏览器解析（兼容）”入口，作为 Hero 入口之外的可发现性保障。

## 组件边界

- 新建 `apps/web/src/components/LaunchPage.tsx`：只负责启航页结构与用户动作回调，不读取项目、支付或简历数据。
- 修改 `BuilderExperience.tsx`：在 `phase="landing"` 时渲染 `LaunchPage` 和现有 `ProjectsDialog`；其他 phase 继续使用 `BuilderChrome`，避免首页样式影响工作流。
- 修改 `styles.css`：新增 `launch-*` 样式和两个响应式断点；不修改内部页面共用令牌的视觉定义。
- 更新 `App.test.tsx` 并新增 `LaunchPage.test.tsx`：覆盖主 CTA、样例滚动/打开、项目弹窗、兼容入口和无假链接。

## 状态与错误处理

- 启航页自身无异步状态；项目数量和项目弹窗仍由现有 `App`/`BuilderExperience` 数据流提供。
- `/upload` 使用原生链接，因此即使 JavaScript 导航状态异常，主路径仍可访问。
- `scrollIntoView` 仅用于站内区块定位；测试环境或不支持该 API 时不得阻断其他动作。
- 项目加载失败沿用现有空列表行为，不在首页新增错误提示。

## 验收标准

- 1440px 下的版式、间距、颜色、边框、字号层级和 Figma `67:74` 一致，允许因真实功能入口产生小范围布局差异。
- 320px 宽度下所有区块保持单列可读，无页面级横向溢出。
- 主 CTA 均指向 `/upload`；样例入口可滚动或打开真实样例；“我的项目”打开原弹窗；兼容入口进入旧解析上传页。
- 页面不包含指向不存在隐私、条款或联系页面的 `<a>`。
- 原有非首页工作流测试不回归；`npm test` 和 `npm run build` 通过。

## 实现者可自行决定的细节

- 在不改变 Figma 信息层级的前提下，可微调手机端字号和间距。
- 可使用 CSS Grid 或 Flexbox，但不得引入布局依赖。
- 首页 hover 可采用轻微颜色和位移反馈，必须尊重 `prefers-reduced-motion`。
