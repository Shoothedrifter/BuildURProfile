# 肖像风格 Skill 与 LangGraph Demo 设计（草案）

日期：2026-10-30。本文记录已确认的产品方向与拟采用的工程方案；不是已上线、已获得商业授权或已完成图像生成的证明。

## 目的与范围

用户在首页选择一张本人肖像照片和一种风格，之后沿用 PDF 提取、字段确认、八题测评与网页预览流程。生成的个人虚拟形象放在作品 HTML 的首屏。这里的“动画版”指动画/插画/玩偶等视觉风格；本次 demo 只展示静态成图，保留各风格自带背景，不做透明抠图、随鼠标转向或 3D 模型。

本次工作的另一个目的，是验证真实可运行的 LangGraph.js 任务图和受限 Skill 适配层。当前仓库只有 `apps/web`、`apps/api` 和 `packages/contracts` 的物理分层；`apps/worker`、LangGraph 任务 API、严格运行时 schema 尚未落地，不能把 `AGENT_ARCHITECTURE.md` 中的目标架构视为现状。

用户选定的初始范围是 Wibi Style 的 `Portraits & selfies` 分类中的三款：

| 用户名称 | Skill ID | 选择原因 | 成图约束 |
| --- | --- | --- | --- |
| 复古扁平动画头（默认） | `retro-flat-anime-head` | 直接呈现电视动画头像，适合未来头部/视线转向 | 大头特写，纯色背景 |
| 蜡笔极简扁平画 | `crayon-flat-naive` | 手绘插画方向，可适配头像、半身或全身 | 白纸面、蜡笔颗粒；需按照片选择参考图 |
| 颗粒绒感玩偶 | `textile-toy-portrait` | 具有立体观感的角色方向 | 白底棚拍、纺织材质；不是 3D 模型 |

风格来源分别为 `https://github.com/Vieeeeeee/wibi-style/tree/main/skills/<skill-id>`。选择时固定具体 commit/版本与文件哈希，不在运行时自动拉取或执行远端仓库内容。第三方 Skill 中的欢迎卡、社群入口、更新检查和脚本不是网页产品流程，也不作为 LangGraph 指令执行。

## 已考虑的方式

1. **一次做完照片、PDF、配置的生成图（选择）**：浏览器先持有照片与 PDF；用户确认内容和测评后，提交一个生成任务。LangGraph 的图包含可跳过的肖像分支，最终形成同一首屏配置。优点是状态、重试与任务归属清楚；代价是要先落地 worker、持久任务和图像服务。
2. **把 Wibi Skill 装在开发者 Codex 环境中，手工生图再上传页面**：能快速看视觉效果，但网页运行时并未调用 Skill，无法验证项目的 LangGraph/Skill 架构，因此不满足本次目标。
3. **本次直接产出可随鼠标转向的 3D 模型或多朝向图集**：超出 demo 范围，且这三款 Skill 输出静态图；会显著增加身份一致性和素材验收成本。

首屏采用固定的、可适配三种背景画面的媒体容器：大字姓名与职业信息保持可读，成图在首屏作为主视觉，移动端改为上下布局。MotionSites 与用户截图只提供构图参考；不复制外部 prompt、远程媒体、品牌或交互代码。

## 用户流程

1. 首页提供可选的单人肖像照片输入与三款风格卡。照片在浏览器内预览；未选择照片时，现有 PDF-only 流程仍可使用。
2. 用户继续上传 PDF，浏览器内提取并确认展示内容，完成八题测评。PDF 字节、原始提取文本和 `sourceRefs` 不发给服务端。
3. 点击生成时，界面明确说明肖像将发送到图像生成服务，并在用户主动提交后发送。前端提供任务进度、失败原因与重新尝试入口；提交前换照片或风格不触发生成费用。
4. 完成后在结果页展示包含成图的首屏，并允许重新选择风格/照片创建新任务。替换成图只改变当前作品的候选版本，不回写旧任务。
5. 本次 demo 的肖像产物只用于预览验收。含 Wibi 肖像的作品由 API 拒绝进入付费分享和 ZIP 交付，前端也不展示相应入口；既有无肖像作品的支付流程不改变。若需要公开部署，本条与存储部署方案需先更新。

## 运行结构与接口

浏览器在用户确认生成前不上传肖像；生成请求包含经过服务端会话与 CSRF 认证的选定 `styleId`、已确认的公开展示字段、职业与测评分数。肖像单独上传到受项目会话保护的临时资产接口，返回 `portraitAssetId`；任务请求只引用这个 ID。服务器验证 MIME、文件头、像素尺寸与大小；界面提示使用清晰的单人照片。自动识别多人/模糊留待后续质量门禁，当前不能宣称已完成。源照片设置短保留期，不写入 `DesignConfig`、图状态、日志或 Git。

`POST /api/generations` 返回任务 ID；`GET /api/generations/:id` 只允许所属会话读取进度、诊断和结果。失败后用户通过重新提交照片创建新任务和新幂等键；独立 retry endpoint 与自动退避留待后续。API 用现有会话/CSRF/所有权机制，任务表和资产元数据持久化在本地 `data/`，worker 使用租约领取，LangGraph 使用持久 SQLite checkpointer 和稳定 `thread_id = generation.id`。重复提交由会话与 idempotency key 约束。`npm run dev` 启动 worker，任务执行不阻塞 API 请求。多实例与公网部署需要共享数据库、资产存储和任务领取机制，不能直接沿用本机文件方案。

建议的图节点：

```text
START → validateInput → validateConfig → 选择肖像分支
  ├─ no photo ─────────────────────────────────────────┐
  └─ photo → loadStyleRecipe → generateAvatar → verifyAvatar ─┤
                                                           ↓
                    assembleHero → validateHero → verifyArtifact → END
```

图状态只存任务 ID、已确认公开内容的清理后配置、风格 ID/版本、资产 ID、首屏引用与节点轨迹。八题评分和配置映射仍由浏览器确定性函数完成；PDF-only 实际不走服务端图。照片二进制、PDF、密钥、完整生成提示词与支付数据不进入 checkpoint。图像调用是唯一必须用模型的节点；简历评分、配置映射、schema 校验和渲染继续确定性执行。用户确认在图启动前完成，不通过 `interrupt()` 重做表单。

`AvatarStyleAdapter` 是项目内部的受限 Skill 合同：声明 `id`、固定版本、输入照片条件、所需参考文件、图片生成参数、成图尺寸/背景、验证规则与来源/许可证元数据。只允许三个已登记 ID；加载本机安装且固定哈希的 Skill 资源，读取必要的风格规则和参考图，不执行包内脚本、网络更新检查或外部指令。适配器明确区分用户照片的内容角色与参考图的风格角色。用可替换 `ImageProvider` 接口接图像编辑服务；首个 demo 计划使用支持多张参考图输入的服务端图像编辑 API，密钥只在 API/worker 环境中，图像生成失败不伪造成功。具体模型名与服务配置由实施计划固定，测试用替身 provider 而真实验收用合成肖像。

对现有合同加入可选 `heroArtwork: { assetUrl, styleId, alt }`，不把文件字节嵌入 LangGraph 状态。API 只返回会话可读的受控资产 URL；预览组件在首屏渲染。真实成图和元数据在服务端持久化，并按保留期清理。现阶段复用 `cleanConfig` 的白名单清理、大小限制和首屏 URL 约束；完整 `SiteSpec` schema 与撤销入口留待后续。失败或无照片时仍可回到文字首屏。

## 权利、隐私和成本边界

Wibi 仓库的自动化脚本与原创风格指令采用不同授权：风格说明、提示词与构图规则只许可个人非商业使用，纳入付费产品或服务需要作者事先书面许可。因此此次设计的 Wibi 运行范围限私有 demo；在取得许可前，公开付费交付不得使用这些规则或产物。安装、复制或改写 Skill 不能替代授权。开发时在界面显示来源和适用范围，记录具体使用版本，不把 Wibi prompt/参考图提交到项目仓库。

只有肖像走图像服务，PDF 不走图像服务。上传前说明第三方图像处理；源照片设置短期自动删除，生成图由用户当前会话管理。日志只记任务 ID、节点名、耗时、错误码和资源摘要，不记照片、生成 prompt 或个人履历。限制照片与生成次数，避免公开免费入口造成不可控调用费用。

## 本次验收

- 三种风格可选，任务实际经过对应的 Skill 适配器和图像 provider；未知 ID 被拒绝。
- 用合成肖像跑通真实图像调用，三个风格都得到可辨人物成图；验证失败明确提示，不默默换风格或宣称成功。
- LangGraph 节点、checkpoint、任务状态、断线刷新、worker 重启恢复和幂等提交有可核查结果；既有 PDF-only 路径仍可完成。
- 成图在桌面和移动首屏可见，姓名与导航可读；外部背景不影响页面结构。结果页能说明使用的风格，且仅当前会话可读取生成资产。
- 检查服务端没有收到 PDF 字节或原文出处，checkpoint/日志中没有照片二进制和密钥；无照片时不调用图像 provider。
- 现有 `npm run build`、`npm test`、`npm run test:payment`、`npm run verify:export` 继续通过。自动化通过不等于已经用真人照片验收，也不等于 Wibi 商业授权。

## 后续工作

1. 对已确认成图做人物抠图和透明底边缘验收，更新首屏摆位；保留带背景版作为回退。
2. 以确认的静态角色为身份基准，用 oil-motion 制作多朝向帧和浏览器指针映射。目标交互是指针横纵位置映射角色左右与抬头/低头两个轴，属于二维随机访问和 `scrub`；透明角色路线采用二维 `alpha-atlas` + `frame-scrub`，在目标 CSS 尺寸、DPR 与采样帧数明确后用 `motion_budget.py --strict` 定稿。若继续保留原风格背景，则背景与人物共同烘焙，二维交互须拆为多条独立片段预算，不能把二维朝向压成单条视频。当前静态图保留为加载失败、触屏无悬停和减少动态效果时的替代。本次不生产运动素材或接入运行时。
3. 获取商业授权或使用独立可商用的原创风格后，再设计公开部署、付费分享与离线 ZIP 的图片快照、资产打包和持久存储。不得把当前 Wibi 试验结果直接接入收费交付。

## 已确认的运行范围

本次先在本机完整环境跑通私有 demo，以真实图像调用验证 LangGraph 与 Skill 适配器，不要求部署到公开网址。若后续要求公开部署，需先重审授权、图像调用额度、滥用控制与持久存储，并修订本设计。
