# Pixel World 作品集架构

## 设计方向

让访客先遇见创作者，再走进她的作品。首页是一段连续的滚动叙事，作品档案嵌在叙事中段，项目有可以单独打开的详情。首页始终提供「查看作品」直达入口，让带着明确目的的访客一键到达档案。当前导出的四视图原型用于识别待替换的页面、导航和样式。本规格取代原 [V1 计划](pixel-world-v1-plan.md) 中的版式、导航和交互设计。

| 参考 | 观察 | Pixel World 的选择 |
| --- | --- | --- |
| [JLD’2nd 首页](https://jld2nd.dev/) | 像素半身像和职业宣言占据首屏，创作者故事以滚动场景展开，窗口式入口将访客引向作品 | 保留角色与大标题的双焦点。用可跳过的短篇自述引出作品，章节指示同时承担导航功能 |
| [JLD’2nd 项目档案](https://jld2nd.dev/projects) | 左栏固定身份与入口，右侧以整行展示项目名称、元数据、预览与操作 | 档案内设置一个窄身份栏。每个项目横跨正文列。移动端将身份栏压成档案标题与项目数量 |
| [高艺云作品集](https://gaocrypto123.github.io/my-portfolio/) | 同一页串起身份、精选作品、履历与联系。项目窗口提供原比例展板和「背景／我的职责／设计选择／交付」，两条无图项目仍可阅读 | 采用同页档案与独立详情窗口。让原比例作品和作者贡献成为详情的主体，纯文字项目使用同等层级的文字版式 |

视觉基底采用接近黑色的墨蓝、暖白正文和现有琥珀强调色，保留 BuildURProfile 自有角色与素材。像素轮廓、硬边窗口和小尺寸等宽字用于角色、导航或文件标签。大标题用现代中文无衬线，工作经历和项目正文采用舒适行高。项目原图保留原色。首屏与章节使用大留白，档案和履历适度加密。模板使用原创图标、文案与场景。

## 页面与访问路径

```text
Pixel World
├── 起点   左侧像素角色，右侧姓名、定位、短介绍和查看作品
├── 关于   一段个人自述，可选的角色视角或创作方法
├── 作品   窄身份栏 + 纵向项目档案
│   └── 项目详情   项目图、背景、个人职责、设计选择、交付或成果
├── 经历   教育、实习或工作、校园、荣誉、能力与其他已公开内容
└── 联系   已确认联系方式、回到起点
```

### 起点与关于

- 桌面首屏约一个视口，角色与职业大标题并排，主要入口落在同一屏。窄屏读序为姓名和定位、主要入口、角色、补充介绍，首屏保留作品入口。无个人图时使用可交付的默认角色。角色位置预留独立资产槽，后续替换不影响正文和页面高度。
- 「关于」用一句标题和一小段自述承接角色，最多再展示一组有内容的观点。角色视角可以支持高艺云这样的「产品思考／交互探索」，但要等作者提供两段独立文案才显示切换。切换只更新关于文案，不改变事实、作品顺序或章节可达性。
- 桌面以带中文名称的章节标记显示阅读位置，窄屏用紧凑的章节菜单。「查看作品」从首屏直达档案。没有作品时入口改指向可读的经历或关于。空章节及其导航项一起省略。

### 作品档案与项目详情

- 档案桌面左栏保留姓名、定位、作品数量和返回起点，右栏是一条项目一行的列表。每行先读名称、一句话说明和已确认的时间／角色／标签，再读作品图和「打开项目」。首张补充图当封面，其余进详情。无图时正文横跨可用宽度，用角色、任务或一句说明构成内容，空图框直接省略。
- 详情按「项目名称与元数据 → 作品画廊 → 正文 → 外部链接」阅读。图片保留比例，长展板可放大和关闭。原始补充链接保留作者命名。桌面打开窗口，窄屏打开全屏详情，详情窗口与档案行读取同一条项目数据。关闭、Escape 或浏览器后退返回档案的原位置和触发按钮。直接打开详情链接时，关闭回到该项目所在的档案位置。
- 设计项目的正文可以组织为「背景」「我的职责」「设计选择」「交付／成果」。有确认内容的块才出现。开发项目同样回答问题、个人贡献、实现与结果，具体字段使用作者确认的内容。若当前条目只有自然段，按段展示。作者提供了过程图、原型或演示链接时才出现相应入口。

### 经历与联系

- 经历集中展示已确认的教育、实习／工作、校园、荣誉、技能和其他内容。带日期的经历用时间线，条目很长时可用原生展开内容。奖项可显示已确认的亮点。引用关联项目需要作者明确建立关系，名称相似或奖项相同不自动生成关联。
- 联系作为结尾场景，只从明确勾选的公开字段和获准展示的链接读取。空联系区省略，仍提供回到起点入口。高艺云站的原简历链接是独立公开资源，通用模板需要作者提供公开链接才展示「查看简历」。

## 从简历到作品

用仓库的 PDF 解析入口在本地对高艺云原件检查条目锚点。它识别出 **Emoji-ing** 和 **玄武探秘** 两个项目，以及 2 条教育、2 条实习／工作、1 条校园、1 条技能候选。公开站有 7 个项目，另外 5 个未被这份 PDF 的项目锚点识别。解析锚点属于编辑前候选，以作者最后核对的条目为准。本次导出样本的两个项目也没有补充图或链接，纯文字档案是首版验收场景。 [高艺云的精选作品](https://gaocrypto123.github.io/my-portfolio/#works)

| 内容 | 现有数据入口 | 如何使用 |
| --- | --- | --- |
| 首页姓名、定位和介绍 | 已选身份字段、角色、核对后的自我评价及网站简介 | 用短介绍构成首屏。作者可在对应字段写入自己的表达，资料有限时用姓名与定位启航 |
| 作品列表和详情 | `resume-v3.sections` 中按 `order` 排序的 `projects`，以 `itemId` 稳定定位 | `title`、`details`、已选 `facts` 提供条目正文。结构依赖明确的事实字段或作者标注的小标题，模糊的原段落原样展示 |
| 作品证据 | 条目 `supplement.text`、`links`、`images` | 作者补上展板、过程图、演示、代码或解释。本文所列的公开站项目和媒体不作为其他用户的模板内容 |
| 履历与公开联系 | 非项目的已确认模块、选中的亮点、确认公开的基本联系字段 | 章节按内容有无生成，模块和条目尊重作者保存的顺序。可选日期、亮点和联系方式按已有公开合同读取 |

在本机验收中，**Emoji-ing** 用于验证情感交互装置的目标、个人职责和交付能否从纯文本读出，**玄武探秘** 用于验证儿童科普、AR 与游戏化流程能否在项目详情中组织清楚。通过作者确认的展板或原型再次检查这两条项目的图文呈现与链接可达性。扩展到公开作品集中的七项需要作者在编辑器补充或授权使用对应资料。首个实现阶段使用现有条目结构，让确认页可以管控每一段对外内容。后续若确实需要专门编辑一句话卖点、双视角文案或荣誉与项目之间的关联，再定义显式结构字段与迁移规则。

## 应用与交付边界

| 层级 | 首个实现阶段 |
| --- | --- |
| 数据流 | PDF 私有上传 → 解析与核对 → 服务端投影已公开确认的 `resume-v3` → 生成固定配置 → Pixel World 的展示模型。前端用纯映射整理章节、元数据与项目，以用户确认的文案、图片和链接为准。保留服务端处理的所有权与联系字段筛选 |
| 渲染 | 由 `ShowcasePage` 选择 `PixelWorldPage`。页面按角色首屏、关于、章节导航、档案、项目窗口、履历和联系拆分。样式限定在 Pixel World 容器内。项目预览、分享和单文件 HTML 共用组件、数据和媒体解析器 |
| 地址与导航 | 编辑预览的导航仅更新当前预览。正式分享保留 `#share=<token>`，用查询参数表示手动跳转或详情，例如 `?section=works&case=<itemId>#share=<token>`。滚动位置变化只更新视觉指示。离线导出使用片段定位章节或项目，例如 `#works`、`#case=<itemId>`。未知项目回到档案。支持后退、刷新和移动端触控 |
| 资产与隐私 | 作品图沿用项目媒体授权，单文件导出内嵌。个人联系字段遵循核对选择，原 PDF、私有来源引用和未公开字段不进入作品包。详情仅渲染确认后的内容与补充项 |
| 模板标识 | 建议继续使用 `pixel-world-v1`，这次改变展示层。采用该策略后，已有在线 Pixel World 分享会随部署更新版式。此前下载的 HTML 仍独立使用。发布前检查是否存在需要保留旧外观的已交付在线链接；确有这类要求时，为新外观分配显式模板版本 |
| 像素角色 | 首次交付使用现有默认角色。作品集可先完整生成、阅读、分享与导出。后续可复用现有 Cloudflare 私有肖像任务，通过角色槽在作者选用后展示候选。正式交付个人 IP 仍需经过资产授权和交付范围的设计 |

首个实现阶段允许正常滚动、导航高亮和轻量窗口反馈。正文随文档自然滚动。窄屏项目按正文顺序折叠，桌面内容遵循 1600px 外层上限。减弱动态效果模式下保留全部内容与操作。项目窗口支持焦点管理、键盘和触控，并避免窗口外的背景继续滚动。小游戏、声音、跟随视线、长程视差和作品搜索可以等内容架构验收之后评估。

## 按 TDD 的实施顺序与验收

先用合成简历、图片和测试链接编写失败断言，再逐段完成渲染与交付。真实简历只在本机作人工验收。

| 顺序 | 先写失败用例 | 验收结果 |
| --- | --- | --- |
| 1. 数据投影 | 两个无图项目、项目缺失、隐藏模块、未公开联系方式、同名项目、项目顺序、长期积累下的长中文文本 | 首屏、关于、作品、经历、联系在同一文档连续呈现。仅存在实际有内容的章节。项目按稳定 ID 定位，空字段不生成标签 |
| 2. 页面与详情 | 首屏直达作品、单项目打开与关闭、第二个同名项目、键盘焦点、无图与图文混排、窄屏导航 | 大屏保留角色与档案的两种视觉节奏。390px 与 768px 宽度下中文标题、展板、跳转和详情都可读可操作。按 Escape 关闭并恢复焦点。减弱动态效果下同样可用 |
| 3. 交付 | 分享链接的详情直达、刷新与后退、恶意外部链接、离线 HTML、旧配置读取 | 分享令牌和媒体权限通过原有机制核验。离线预览中默认角色、图文和详情操作可用。对既有模板运行回归验证 |
| 4. 本机样例 | PDF-only 导入，再为两个项目补展板或演示作对照 | 高艺云的两个 PDF 项目都进入档案；没有配图时可直读角色与贡献；补充资料后详情可以展开，项目不会增生或重复。使用合成开发项目复查同一架构可表达实现与结果 |

Web 验收运行 `npm test` 与 `npm run build`，执行桌面宽屏、窄屏及离线导出浏览器检查。交付接口有改动时加 `npm run test:payment`。若后续引入公开合同字段，再同步 Node、Python、Schema 和黄金样例。 [项目检查要求](../../AGENTS.md) · [架构与协议](../shared/architecture.md)
