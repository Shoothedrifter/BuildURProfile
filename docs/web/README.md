# Web（Next.js 全栈应用）

`apps/web` 是基于 Next.js（App Router）+ React + TypeScript + Tailwind CSS 的全栈应用。新简历流程上传 PDF 并交给 Python Agent 解析，前端负责核对、固定模板选择、生成进度、编辑和作品展示；服务端通过 App Router Route Handlers 提供会话、私有 PDF、解析任务、资产、支付与作品集交付接口。

## 用户流程与边界

PDF → 首页 `/#upload` 私有上传 → Web 复用浏览器解析算法固定模块和条目 → Agent 对齐来源并逐条排版 → `/editor/:resumeId` 对照原 PDF 核对、排序和补充内容 → `/style/:resumeId` 选择职业和固定模板 → 提交 `resumeId/revision/role/templateId` → Python Agent 生成配置 → 编辑与预览 → 免费导出个人作品集网页或付费发布分享。像素世界风使用 `python-agent-v7`，其他固定模板使用 `python-agent-v6`。新流程无需填写测评答案。

首页导航可直达功能演示、风格样例、上传和试玩工作台。试玩使用合成简历，可调整首屏、模块和五套模板，草稿保存在当前浏览器。正式上传、草稿和交付由当前会话管理。旧 `/upload` 地址重定向至首页上传区。

- 新流程的原 PDF、来源块、私有草稿和最近 10 版历史从上传起在受会话保护的服务端保留 30 天，可提前删除；Agent 仅向当前配置的 OpenAI 或智谱 GLM 文本供应商发送逐条格式化必需的文字。扫描件普通解析失败后可主动选择本机 OCR；混合 PDF 成功解析后可对无文字页创建独立 OCR 候选，核对后补空应用。OCR 所需的系统组件见[部署说明](../shared/deployment.md)。
- 首页保留明确标注的“浏览器解析（兼容）”入口；该旧路径的 PDF 与候选内容仍只留在浏览器内存。新流程模型失败时不会回退到旧路径并假称 AI 解析成功。
- 确认页覆盖基本信息、求职意向、自我评价、教育、实习/工作、项目、奖项、校园、技能和其他内容。新版 Agent 流程按模块决定普通内容条目展示；基本信息仅供核对网站姓名与联系字段，不生成独立展示分区；工作与校园经历分别核对。旧浏览器兼容入口产出带来源、页码和展示选择的 `ResumeCandidateV2`，工作与校园经历是两个独立数组。个人细节与期待薪资默认关闭。新流程确认后生成 `resume-v3` 展示内容，旧入口保留 `resume-v1` 兼容；来源页码和原文不会进入生成 brief。
- **产品本体 vs. 交付产物**：`apps/web` 是生成器产品本体（全栈应用），不部署到 GitHub Pages；用户生成的**个人作品集页面（Showcase）**才是最终交付产物。

配置 GitHub OAuth 后，解锁并发布分享链接的项目可在「正式链接已创建」面板中选择「部署到 GitHub Pages」。填写新仓库名称并确认公开，使用当前项目的付费分享资格，再到 GitHub 授权。发布完成后可打开网站或仓库，关闭对话框后可从部署记录继续查询。站点由用户在 GitHub 上管理。 [部署配置](../shared/deployment.md#github-pages-授权与验收)
- 肖像是可选内容；照片在主动提交前只留在浏览器。提交时须说明会交给图像供应商处理。

结果工作台左侧展示可缩放的站点，右侧提供「内容」「样式」「设置」。可打开当前快照到新标签页、保存项目草稿或返回核对详细资料。更换模板通过风格页显式重新生成。点击发布后，右侧面板继续处理公开确认、权益、支付宝查单和分享链接。免费导出按钮直接下载单文件 HTML。远程编辑图片需通过浏览器 CORS 读取并嵌入为 Data URL，才能用于作品集发布与导出。

“我的项目”支持二次确认后删除：已打开的项目删除成功后返回首页，现有分享和未使用的下载链接失效；待核实支付订单的项目会显示服务端拒绝原因。

“赛博科技”按显式 `cyber-creator-v1` 进入独立页面：首屏将已确认的两字汉字姓名完整显示为“你好，我是{姓名}”，三字及以上汉字姓名取末两字；顶部导航不重复全名，完整姓名与已选邮箱、电话集中在底部联系区。模块标题采用灰蓝渐变，浅色能力区使用深色渐变；工作经历模块以标题跑马灯开场，显示已确认的经历标题，不再用技能或项目图片填充跑马灯。项目图片与文字进入深色项目区，其余模块按确认顺序显示。图片从原条目的补充资产 ID 读取；无图片时展示文字。预览与分享按滚动横移工作标题，触屏和离线导出自动横移，减少动态效果时静止。其他模板与旧作品沿用原有骨架，旧 `dark-tech` 作品不会自动换成新页面。详细映射见[赛博科技模板规格](cyber-creator-p0-spec.md)。

## 页面宽度与响应式布局

桌面主要页面的外层内容宽度上限为 `1600px`，具体内容受内边距和各栏宽度约束。核对页给核对清单分配 `170–245px`、给 PDF 分配 `240–340px`，正文使用剩余空间。`1100px` 以下 PDF 移至两列下方，`760px` 以下为单栏。风格页左侧样张约占可用栅格的 65%，右侧设置保留至少 `360px`，`800px` 以下为单栏。结果工作台右栏宽 `330–380px`，`960px` 以下预览和编辑面板依次排列。

## 开发与验证

在仓库根目录运行 `npm run dev`，由 `apps/launcher` 启动 Next.js 开发服务与 Python Agent。完整环境与端口配置见[部署说明](../shared/deployment.md)。

```sh
npm test
npm run build
```

前端单测使用 Vitest（配置见根目录 `vitest.config.ts`），测试文件分布在源码旁，测试初始化位于 `src/test/setup.ts`。服务端接口与启动器说明见[API 与 Launcher](../api/README.md)。

## 核对与补充内容

核对页保留三栏原 PDF 对照和逐条来源摘录。低置信度条目须明确点击「已核对」，编辑内容不会自动确认；置信度提示仍保留。隐藏待核对模块需要确认，完成后才清除该模块的待核对标记。未完成核对不能进入风格页。新版页面已移除条目级“展示此条”：开启模块后，该模块全部条目按用户顺序进入作品；关闭模块则全部不展示。`item.included` 仍在旧草稿合同中，但不再控制新版投影。姓名和邮箱/电话的字段级“用于网站”选择控制公开联系信息；基本信息模块不再有总开关，姓名和联系方式检查只依据已选择字段。年龄等其他基本信息与补充内容不进入新作品。

每条可补充 500 个 Unicode 码点、5 个 HTTP(S) 链接（名称可选）和 6 张图片。全份上限为 24 张 / 50 MiB、单张 5 MiB；上传实际格式和尺寸由服务端复核。上传中移动条目按稳定 ID 归位，删除条目则释放迟到图片；未保存就刷新时，可从「管理未保存图片」恢复或删除占用额度的上传。保存时丢弃完全空白的链接行，有名称无 URL、非法协议或超限时定位模块并阻止提交。显式保存使用 revision 检测冲突，失败保留本地修改。

校园经历和荣誉奖项的「作品集成果」允许核对 PDF 来源、编辑数字和勾选「突出展示」。首次进入时，能在该条目的公开原文中核实且与展示内容无冲突的候选默认勾选。用户调整过成果后，后续生成以保存的勾选为准。取消全部勾选后，正文及详情继续按模块的公开设置展示。旧条目沿用已确认正文识别成果，也可直接开启手动管理。已勾选成果与正文存在明确的数值冲突，或包含未公开字段时，编辑器会提示核对，作品集暂不展示该数字。

头像风格由网站模板决定。赛博科技使用「低清晰印刷感动漫」。像素世界风的默认角色使用设计稿 `pixel-world-base.svg`，预览和分享读取静态资源，单文件 HTML 将同一 SVG 内嵌。生成基础作品后，本机作者点击「识别照片特征」才上传。短发、齐肩发、长发、单马尾、双马尾和刘海可与粉色等发色及镜框组合。选用后在当前预览查看，刷新、分享和导出使用默认角色。旧头像配方继续服务已入队的旧任务。

新流程生成只提交已保存的 `resumeId/revision`、角色和 `templateId`，服务端重新投影。`resume-v3.sections` 按用户确认的模块和条目顺序进入预览、项目编辑、分享和导出。赛博科技项目使用独立拼贴卡片，像素世界风使用连续滚动章节、整行作品档案和项目详情窗口，其他模板使用 StackedCards。像素世界风首屏可直达作品，详情保留已确认的项目正文、媒体和作者命名的链接。分享地址保留 `#share=<token>` 并使用查询参数定位项目，单文件 HTML 使用片段定位。正文保留换行，补充信息跟随原条目。像素世界风的章节与文件标签使用 Fusion Pixel 12px 中文等宽字体（OFL 许可，随仓库分发，完整字体不进公开目录）：页面经 `/api/pixel-font` 按需子集化 woff2，单文件导出内嵌 data URI 子集。草稿编辑 800 毫秒后串行自动保存，显式保存会提示结果。无肖像生成成功会在「我的项目」出现未付款草稿。 [Pixel World 作品集架构](pixel-world-architecture.md)

私有原件到期后，已有项目图片继续通过独立作品资产读取。图片权限及保留规则见[架构与协议](../shared/architecture.md#简历图片与作品资产)。旧 `resume-v1` 项目继续使用兼容展示和编辑路径。
