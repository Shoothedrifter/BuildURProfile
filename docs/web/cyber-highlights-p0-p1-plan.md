# 校园成果与荣誉统计一致性 P0/P1 实施计划

**状态**　已在本地 `dev/noodle` 实施。两份原始导出的共同数据均可识别。合成 PDF/OCR 测试、生成预览、分享快照和离线导出回归覆盖已勾选及关闭高亮的状态。

导出 13／14 回归补充覆盖「包括」以及冒号引出的分级计数。未操作成果区时，默认突出公开原文能核实且无冲突的候选，首次修改成果后保存当前勾选。已导出文件中的空数组仍代表关闭高亮。

**目标**　同一项已确认成果在摘要措辞、标点或换行变化时保持稳定。已有作品先通过 P0 获得兼容，P1 把成果展示权交给「解析与补充」里的确认字段。

**架构**　P0 改进赛博科技渲染器的一项输入适配。P1 在私有草稿保存可核对的候选，在公开展示合同中只投影用户选中的成果。预览、分享和 HTML 导出共用同一套展示规则。

**依据**　[可选分区实施计划](cyber-optional-sections-plan.md) 与 HTML (11)/(12) 的复现。两份导出的 CSS 和 JavaScript 相同，两类条目的 `facts` 都为空。HTML (11) 展示 4 个荣誉数字、2 项校园成果；HTML (12) 展示 0 个荣誉数字、1 项校园成果。HTML (12) 的荣誉 `sourceText` 为空，详情入口按现有条件省略。

**约束**　在 `dev/noodle` 实施。模块可缺失或隐藏，纯文字也可独立展示。沿用已确认的条目顺序和公开边界。证明素材及原文继续随原条目保留。测试只提交合成样例，真实 HTML 两份仅在本机用于回归。

## P1　在解析与补充中核对成果字段

### 1. 定义草稿与公开投影合同

- [x] 在 `packages/contracts/src/config.ts` 定义可选 `presentationHighlights`。公开元素使用三种类型：`campus-metric` 保存 `id / label / value / unit`，`award-total` 保存同一组字段，`award-tier` 另含明确的 `level`。`value` 使用规范化数字字符串；院校实践可用百分比、百分点或已明确标注的计数单位，奖项使用整数及「项／个／次」。保留原文指标名和级别的语义，省级与省部级各自独立。
- [x] 私有草稿的 `presentationHighlights` 额外保存是否选中、候选来源及用于核对的条目内证据引用。自动候选默认未选中。用户可以新加、编辑、择优展示或全部关闭。候选来源、未选中项和证据定位留在草稿，公开投影只允许经确认的展示数据。
- [x] 区分缺字段、空数组和有值三种情况。**缺字段**代表旧条目，允许 P0 兼容提取。**空数组**代表已启用结构化管理、当前没有选中成果，直接保留正文。**有值**代表仅用已选字段展示。三态经过保存、生成、分享和导出必须保持原样。
- [x] 在 `packages/contracts/src/resume-draft.ts` 的 `projectConfirmedResumeV3` 按已有可见模块和原 `itemId` 投影，校验字段与所属模块匹配、单位有效、ID 唯一，单条最多一个总数，同级别不能有相互冲突的已选值。确认成果可以构成有效公开内容，未确认候选不会生成空模块。同步更新 `resume-v3.mjs`、受影响的 JSON Schema、Python `contracts.py` 和契约样例。旧版本读者继续接收原格式，先部署兼容读者再启用新写入。
- [x] 成果选择与字段隐私分开。「突出展示」关闭后，已公开正文仍按原样显示，旧文本识别不会补回已关闭的成果。既有字段隐私约束检查成果标签、值和单位组合，避免已取消公开的信息从数字卡片进入作品集。确认与拒绝用两个独立测试覆盖。

### 2. 在解析阶段生成可核对候选

- [x] 在 `apps/agent/src/buildurprofile_agent/skills/anchored_formatter.py` 的草稿构建阶段接入成果候选提取。只扫描已经归到同一条目的来源块，按可验证的「标签 + 数值 + 单位」提取，不读取其它条目，也不根据 LLM 摘要捏造数值或合成总数。同一来源以两种模型摘要格式格式化时，候选集合应一致。
- [x] 保留原文与候选的对应证据，缺少可靠证据或同一范围内存在冲突时留待人工填写。候选提取失效属于可选展示降级，原简历解析及正文不受阻。P1 先采用确定性候选提取，未来若引入模型建议，仍须通过同一套数字、标签、单位和证据校验。
- [x] 给新解析输出分配新工作流版本，同步 `graphs/resume_parse.py`、`transport/node_api.py` 和 `packages/storage/src/resumes/queue.mjs` 的版本分派及 OCR 路径校验。旧租约、checkpoint、候选、草稿和既有作品继续按旧版本读取。给常规解析和 OCR 各自增加版本、失败降级及同源异措辞的回归样例。
