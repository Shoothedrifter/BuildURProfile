# “赛博科技”固定作品集模板 P0 规格

状态：P0 已实施并完成本地验收。参考材料为用户提供的 MotionSites “3D Jack Portfolio”设计 Prompt；本规格描述 BuildURProfile 的产品行为，不要求运行时访问 MotionSites。

## 目标与范围

“赛博科技”作为用户可选的固定模板，呈现参考 Prompt 的构图语言：暗色满屏人物首屏、靠近顶部的超大渐变招呼语、实习/工作经历标题跑马灯、居中的 About、圆角浅色能力区、深色项目堆叠区。作品的事实、图像和链接只来自用户确认的简历与补充内容。现有其他风格、旧作品和运行中的旧任务继续可用。

P0 交付从 `/editor/:resumeId` 核对与补充，经 `/style/:resumeId` 模板选择、Python 生成，到预览、编辑、单文件导出和授权分享。所有新简历生成任务仍经过 Python 图；不调用 MotionSites MCP，不运行任意模板代码，不生成新的简历事实。

## 设计取舍

1. 保留参考 Prompt 的层次、比例、黑白节奏、动效语义，不照搬 Jack、五项服务、项目名称、价格导航、21 张 GIF、外部项目图或第三方肖像 URL。Prompt 的 `Price` 导航没有对应章节；产品不显示无依据的价格入口。
2. 复用 Next.js、React、现有 CSS 与受控展示合同。Prompt 中的 Vite、React 18、Tailwind 3、Framer Motion 是示例技术选型，不构成迁移要求。需要滚动与指针动效时，选可清理监听、支持减少动态效果且在导出 HTML 中运行的实现。
3. 用户确认的 `resume-v3.sections` 是唯一内容真源。普通内容模块开关、模块顺序、条目顺序和字段级隐私选择均生效；基本信息仅作为网站身份与联系数据，不生成展示分区；旧 `item.included` 不参与新版投影。来源摘录、PDF 原文、隐藏字段不进入模板、跑马灯、页面元信息或导出。
4. “赛博科技”使用独立模板标识和模板版本，不能仅通过 `skin: dark-tech` 或八题预设答案推断。旧 `dark-tech` 配置继续按原渲染器显示，避免已交付作品外观突然改变。

## 输入与生成合同

- 新简历生成请求包含 `resumeId`、`revision`、`role`、`templateId`、`idempotencyKey`，及可选的现有肖像参数。`templateId` 采用固定目录：`cyber-creator-v1`、`warm-v1`、`minimal-v1`、`bold-v1`。新请求不携带 `answers`；旧任务仍按各自工作流和合同读取答案。
- 服务端在同一事务中核验会话归属、保存版本和图片归属，重新投影确认内容。幂等键绑定模板 ID；相同键与不同模板必须冲突。新 `GenerationBriefV4`、`DesignConfigV4` 与工作流版本独立于现有 V3/v4。V4 配置包含 `templateId` 和既有受校验字段；兼容字段 `skin/styleVector/marquee/stackedCards` 由固定模板目录确定，不能由客户端提交任意样式代码。
- Python 图以固定模板映射节点代替八题评分节点，保持内容组装、可选肖像、QA、租约和 checkpoint 边界。QA 核对生成后的确认内容与输入完全一致。TS/Python 的模板目录值有跨语言黄金样例。
- 旧 `GenerationBriefV1–V3`、`DesignConfigV1–V3`、旧队列任务及现有作品不迁移到新模板；预览/分享/导出根据显式 `templateId` 选择渲染器，缺失时走旧路径。

## “解析与补充”到页面的映射

Hero 是页面框架；实习/工作经历模块以跑马灯作为唯一标题，正文紧随其后。实际内容模块按 `resume-v3.sections.order` 呈现，每个模块内部按条目顺序呈现。模板可给模块不同的视觉容器，但不得重排、合并、复制或遗漏有内容的条目。首屏昵称由已确认姓名派生，不生成新事实。

| 已确认模块 | 赛博科技呈现 | 数据边界 |
| --- | --- | --- |
| 基本信息、求职意向 | Hero 显示“你好，我是{称呼名}”；完整姓名与已选邮箱、电话集中在底部联系区；求职意向按内容呈现 | 不生成基本信息分区；年龄等其他个人信息不进入新作品；无联系方式不显示联系入口 |
| 自我评价 | 暗色 About，长文按段落/换行完整保留 | 没有内容则不显示；动画不改变可复制文本或阅读顺序 |
| 专业技能 | 白色圆角“能力与专长”编号行，长技能保留全文 | 不称为用户提供的商业服务，不伪造 Prompt 的五项服务 |
| 项目经历 | 深色堆叠项目卡：序号、标题、已有说明/事实、图片、链接 | `itemId` 绑定补充资产；不自动标记 Client/Personal、年份或 Live Project |
| 实习/工作经历 | 大号渐变跑马灯展示模块标题和已确认的条目标题，经历正文紧接其后；不重复放普通标题 | 仅取可见工作条目；保留正文换行、事实、补充文字、链接及图片 |
| 校园、教育、荣誉、其他 | 深色内容区，模块标题使用同一渐变字体系 | 保留标题、正文换行、事实、补充文字、链接及图片；不塞入无关项目卡 |

项目卡的图片直接读取该条 `supplement.images`：0 张为有视觉设计的文字卡，1 张为单图，2 张为双图，3 张以上使用“左二右一”拼贴；第 4–6 张在同卡可展开画廊中可见。第一张为主图，顺序沿用解析页，不复制成新的 `ProjectCard.image` 数据源。所有补充文字与事实完整可达，卡片首屏可以摘要，但必须提供展开全文。链接使用该条已确认的命名链接；没有链接不显示“查看项目”按钮。项目数量不限于 Prompt 的三项，0 项时不显示空项目区。

跑马灯只读取可见实习/工作经历条目的已确认标题：先呈现“实习/工作经历”，再按条目顺序呈现岗位或经历标题。没有可见工作条目时不显示跑马灯；不以技能、项目图片或外部 GIF 填充。项目图片仍只出现在对应项目卡中，通过现有 `imageId` 与会话/分享媒体解析器读取；离线导出内嵌所引用的图片。

## 视觉、动效与资产

- Hero 占据首屏主体；顶部导航使用中性作品集标识，不重复完整姓名。主标题为“你好，我是{称呼名}”：两个汉字显示全名，三个或四个汉字取末两字；更长的纯汉字姓名同样取末两字，非汉字姓名取第一个空格分隔的名字。完整姓名只在底部与已选邮箱、电话集中展示。人物位于大字前景，宽屏与预览容器均需保持文字可读；标题、正文和按钮保持可选中、可键盘访问。
- 无照片使用专门创作且已审查使用权的匿名立体人物资产。用户照片路径在取得可商用的肖像生成/资产权利前，继续遵守现有仅限本机演示的交付限制；不得把当前 Wibi 二维头像宣称为 3D 人物或绕过分享限制。P0 的可正式交付路径须有无照片方案。
- 所有模块标题沿用参考 Prompt 的灰蓝渐变字；浅色能力区改用更深的渐变以保证对比度。浅色能力区与深色项目区保留圆角衔接、大号章节标题、编号和拼贴比例；色彩集中于人物与 CTA。工作经历跑马灯在普通页面随滚动横移，触屏与离线导出使用轻量自动横移动画；`prefers-reduced-motion` 下保持静态。动画不得阻断内容读取。
- 不热链 Prompt 的肖像、GIF 或项目图片；外部资源的许可和交付能力未确认前不得进入正式产物。

## 验收

1. 以无照片、0/1/3+ 项目、0/1/2/3/6 张项目图、两/三/四字中文姓名、空联系方式、仅工作或仅技能模块的合成样例验收。首屏称呼与底部完整姓名分别正确；没有工作经历则不出现跑马灯。已确认模块和条目按顺序完整出现，图片始终跟随原条目，0 图不显示伪造作品图。
2. 对照 Prompt 在 1440×900、768×1024、390×844 检查首屏构图、深浅章节、标题渐变、工作经历跑马灯、项目拼贴和移动端阅读；检查离线 HTML 的自动横移及减少动态效果回退。不要求复用原图或逐像素复刻。
3. 隐藏模块、未选字段、来源摘录在生成配置、DOM、分享快照和导出 HTML 中均不可见。编辑后的预览、分享和导出使用同一模板及媒体引用；分享/导出仍由原服务端权限规则控制。
4. `npm test`、`npm run build`、`npm run test:skills`、`npm run test:agent`、`npm run test:payment` 通过；浏览器验证键盘导航、触屏与减少动态效果。旧作品、旧生成任务和其他风格有回归测试。
