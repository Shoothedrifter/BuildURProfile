# 暖调马卡龙作品集架构

## 设计方向

第三张独立作品集模板页面，接替「温暖创意」在选择器的位置。设计蓝本为需求方授权采用的个人网页设计（葛纳原站静态稿）：固定马卡龙对角渐变底上以毛玻璃卡片逐屏展开简历模块。模板交付只采用原站的版式、配色与交互，页面内容全部来自用户核对后的简历数据与主动提交的照片；原站的照片、简历内容与联系方式不进入仓库、模板资源或自动测试。

| 参考 | 观察 | 暖调马卡龙的选择 |
| --- | --- | --- |
| 原站首屏 | 固定对角渐变底上，左侧衬线大姓名、求职岗位与介绍盒，右侧外扩描边相框大照片，屏幕两侧半透明气泡上浮 | 保留渐变底、相框与气泡；姓名、岗位、自述来自核对字段，照片由用户提交的原图直出 |
| 原站教育卡 | 图片在上信息在下，卡内以高亮数字呈现成绩与荣誉 | 教育条目首张补充图作卡面，facts 与已确认亮点构成成绩行；无图时纯文字卡 |
| 原站经历/项目/媒体卡 | 横向图卡、粉点条目列表、「了解详情／查看作品」打开详情与轮播模态 | supplement 图文进入卡片与模态；灯箱、详情与轮播读取同一条目数据 |
| 原站技能区 | 分组卡片与蓝粉双色 chip，区尾版权行 | skills 条目即分组，facts 逐项成 chip |

视觉基底：`#E0A6B5 → #FED2BC → #DEEDC3` 固定对角渐变底（`background-attachment: fixed`，滚动时卡片浮于渐变之上）；`rgba(255,255,255,0.6)` 毛玻璃卡片配 16px 圆角与浅阴影；Noto Serif SC 衬线标题（小号英文 eyebrow 加 28px 中文大标题的双标题制）配 Noto Sans SC 正文，字体加载沿用现有机制并提供系统衬线降级；强调色粉 `#D4A5A5/#E8C4C4/#B5828C` 与蓝 `#B5D0D9/#D0E3EB`，正文暖梅 `#4A3840`；导航与模态遮罩使用半透明加模糊。默认图与全部文案为原创资源。

## 页面与访问路径

```text
暖调马卡龙
├── 关于我   左侧文字（问候、姓名、求职岗位、介绍盒、联系入口），右侧照片相框，气泡背景
├── 教育背景  图片毛玻璃卡纵排，卡内成绩与荣誉亮点行
├── 工作/实习  横向图卡 + 粉点条目列表
├── 项目经历  双列图卡 + 「了解详情 →」详情模态
├── 展示区    媒体/校园/荣誉等模块的展示卡 + 「查看作品 →」轮播模态
├── 个人技能  分组 chip 卡
└── 区尾     版权行（技能区内）
```

- **分幕节奏**：每个区块至少占一屏（`min-height: 100vh`），底部居中「继续下滑，探索更多」按钮平滑滚至下一区，最后一区不放置。固定半透明导航锚点跳转并随滚动高亮当前区。区块按 `resume-v3` 实际有内容的模块生成，空模块连导航项一起省略。
- **首屏**：问候语 + 姓名大衬线 + 求职岗位（`jobIntent`）+ 粉色左边框介绍盒（`selfEvaluation`）+ 联系按钮。原站「下载简历」按钮不保留——PDF 原件是私有数据，不进入公开作品。联系按钮仅在已选公开联系字段非空时出现，打开联系模态。
- **照片（原图直出）**：用户主动上传的照片经私有资产直达首屏相框，不经图像供应商、不生成头像；未上传时使用原创柔和默认图（非真人、非 Wibi 资源）。相框保留外扩细描边与悬停轻微放大。上传界面沿用照片传输披露，并说明本模板将直接展示原图。
- **教育卡**：条目首张补充图为卡面，学校、学历与时间为信息行，`facts` 中的成绩、排名等结构化事实构成高亮数字行；无图条目省略图片区，正文横跨卡宽。`presentationHighlights` 存在才渲染，且只出现在其所属条目（荣誉、校园经历展示卡），v1 不为教育扩展提取管线。
- **展示区**：`campusExperience`、`other` 与 `awards` 中已勾选展示的条目按保存顺序渲染为展示卡（对应原站自媒体卡）：标题、正文段、facts chip、首图卡面、多图进轮播模态。模块无内容时整个区块与导航项省略。
- **模态四件套**：图片灯箱（全部内容图可点开）、项目详情（名称与元数据 → 图画廊 → 正文 → 外部链接）、作品轮播（前后按钮 + 圆点指示器，支持键盘）、联系卡（电话、邮箱等已选公开字段）。Escape 或点击遮罩关闭，关闭后恢复触发焦点与正文滚动；详情内点图升级为灯箱的嵌套关闭顺序沿用像素世界风约定。
- **响应式与动效边界**：桌面内容列约 1100px（在 1600px 外层上限内）；900px 起单列堆叠；600px 起汉堡导航、首屏改上图下文、按钮全宽。气泡浮动、卡片悬浮、平滑滚动在「减弱动态效果」偏好下停用或降级为静态呈现，全部内容与操作保持可达。

## 从简历到作品

| 内容 | 数据入口 | 如何使用 |
| --- | --- | --- |
| 首屏姓名、岗位、自述 | 已选身份字段、`jobIntent`、核对后的 `selfEvaluation` | 构成首屏文字侧；资料有限时以姓名与岗位启航 |
| 首屏照片 | 用户提交的私有照片资产（原图直出字段） | 相框直接展示；预览、分享与单文件导出三场景一致 |
| 教育卡 | `education` 条目 `title/details/facts`、`supplement.images` | 首图为卡面，其余图可点开灯箱；facts 中有值的成绩字段渲染为高亮数字行 |
| 工作/实习卡 | `workExperience` 条目与 supplement | 横向卡，图片列最多取前两张补充图，粉点列表按段展示 `details` |
| 项目卡与详情 | `projects` 条目、`supplement.text/links/images` | 卡面读名称、时间、一句话说明与首图；详情收纳其余图、补充说明与外部链接 |
| 展示卡与轮播 | `campusExperience`/`other`/`awards` 条目与 supplement | 展示卡承载标题与正文，多图轮播；空模块省略 |
| 技能分组 | `skills` 条目 | `title` 为分组名，`facts` 逐项渲染为 chip，`details` 作分组说明 |
| 联系模态 | 显式勾选公开的基本联系字段 | 只读确认字段，未公开字段不出现 |

图片规则：卡面取条目首张补充图，无图省略图片区；详情与轮播收纳其余图并保留原比例。外部链接保留作者命名并沿用现有恶意外链校验。

## 应用与交付边界

| 层级 | 决定 |
| --- | --- |
| 数据流 | PDF 私有上传 → 解析与核对 → 服务端投影已确认的 `resume-v3` → 生成固定配置 → 展示模型。前端纯映射整理区块、元数据与条目，保留服务端的所有权与联系字段筛选 |
| 渲染 | `ShowcasePage` 在 `templateId === "warm-macaron-v1"` 且 `resume-v3` 时分发 `WarmMacaronPage`。页面按首屏、区块导航、模态拆分组件，样式限定在模板容器内。项目预览、正式分享与单文件 HTML 导出共用组件、数据和媒体解析器 |
| 模板注册 | 合同 `TemplateId` 与两份 v4 Schema 枚举新增 `warm-macaron-v1`，同时保留 `warm-v1`（存量项目继续通过校验并用旧骨架渲染）。TS 与 Python `TEMPLATE_VECTORS` 追加与 warm-v1 相同的向量（`E=0.75, K=0.5, P=0.5, S=0.5, PChoice="warm"`）。选择器与 demo 展示用「暖调马卡龙」替换「温暖创意」入口，可选模板总数维持五个；原问答自动匹配到 warm 的路径改落 macaron。首页 journey 长卷的暖段落按马卡龙渐变与毛玻璃重做原创段落视觉，默认选中与 demo 默认草稿同步切换到暖调马卡龙 |
| 照片直出 | `DesignConfigV4` 新增可选原图资产字段（资产地址 + 替代文本），由 Web/存储侧在任务完成与项目保存时写入，Agent 图与私有协议不感知（同 `heroArtwork` 先例）。原图为**正式交付能力**：预览走会话资产、分享走令牌核验；保存项目时照片内嵌进配置，不依赖 `avatar_assets` 的 30 天留存，导出沿用内嵌。Schema、TS 合同、Python 合同与黄金样例同步更新 |
| 照片门控 | 现有「照片生成仅赛博科技支持」及「仅本机演示环境开放照片」的门控为 macaron 直出放开生产路径：上传即进预览、无生成任务；上传披露文案修订为「存储于私有资产区并在作品集直接展示，不发送给图像生成供应商」。替代文本由姓名自动生成 |
| 地址与导航 | 编辑预览的导航仅更新当前预览。正式分享保留 `#share=<token>`，手动跳转与详情直达用查询参数（同像素世界风：`?section=&case=<itemId>#share=<token>`）。离线导出用片段定位区块或条目；未知条目回到所在区块 |
| 资产与隐私 | 原 PDF、`sourceText`、私有来源引用与未公开字段不进入作品包。默认图为原创资源；用户照片为本人肖像，按现有照片政策存储并在上传时披露用途 |

## 按 TDD 的实施顺序与验收

先以合成简历、合成图片与测试链接编写失败断言，再逐段完成渲染与交付。真实简历与真实照片只在本机作人工验收。

| 顺序 | 先写失败用例 | 验收结果 |
| --- | --- | --- |
| 1. 合同与数据投影 | 新 `templateId` 校验、照片直出字段、`warm-v1` 存量配置读取、空模块省略、无图条目、未公开联系方式、同名条目、长期积累下的长中文 | 六类区块在同一文档连续呈现，仅存在实际有内容的区块；条目按稳定 ID 定位；空字段不生成标签；旧 warm-v1 项目仍走旧骨架 |
| 2. 页面与模态 | 分幕滚动与导航高亮、四类模态的开关与焦点恢复、轮播键盘操作、项目详情、减弱动态效果、390px/768px/1440px 宽度 | 桌面保留渐变底与毛玻璃的视觉节奏；窄屏中文标题、图片、跳转与模态可读可操作；Escape 关闭并恢复焦点 |
| 3. 交付 | 分享令牌与媒体权限、详情直达的刷新与后退、恶意外部链接、离线 HTML 内嵌照片与多图、旧配置回归 | 分享与离线导出沿用原有核验机制；导出内原图与补充图可用；既有模板回归通过 |
| 4. 本机样例 | 合成简历全模块 + 授权真实样张对照 | 有图/无图、有/无照片、有/无公开联系字段的组合均正确呈现；条目不增生不重复 |

Web 验收运行 `npm test` 与 `npm run build`，执行宽屏与窄屏浏览器检查；合同与照片字段改动同步 Node、Python、Schema 与黄金样例并运行 `npm run test:agent`；照片门控与保存/分享/导出链路属于存储与交付接口改动，加运行 `npm run test:payment`。实施前阅读 `apps/web` 内 Next.js 特殊版本文档（`node_modules/next/dist/docs/`）。同步更新 [AGENTS](../../AGENTS.md) 的模板清单与照片表述、[文档导航](../README.md)。 [项目检查要求](../../AGENTS.md) · [像素世界风架构参考](pixel-world-architecture.md)
